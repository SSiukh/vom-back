# VOM SYSTEMS — Схема бази даних (MongoDB)

> Кожна колекція містить службові поля: `_id` (ObjectId), `created_at` (Date), `updated_at` (Date). Нижче вони не дублюються в кожній таблиці окремо, а винесені як загальне правило.

**Загальні службові поля (є в усіх колекціях):**

| Поле         | Тип      | Призначення                             |
| ------------ | -------- | --------------------------------------- |
| `_id`        | ObjectId | Унікальний ідентифікатор документа      |
| `created_at` | Date     | Дата та час створення запису            |
| `updated_at` | Date     | Дата та час останнього оновлення запису |

## 📁 Основні колекції

### `users`

> Користувачі адміністративної панелі, авторизація та 2FA

| Поле                    | Тип           | Призначення                                                        |
| ----------------------- | ------------- | ------------------------------------------------------------------ |
| `login`                 | String        | Логін користувача (унікальний)                                     |
| `password_hash`         | String        | Хешований пароль                                                   |
| `two_fa_enabled`        | Boolean       | Статус налаштування 2FA                                            |
| `two_fa_secret`         | String        | Секретний ключ для Google Authenticator (зберігається зашифровано) |
| `two_fa_recovery_codes` | Array<String> | Список резервних кодів відновлення (зберігаються хешовано)         |
| `refresh_token_hash`    | String        | Хеш (SHA-256) поточного дійсного refresh-токена, для можливості відкликати сесію при виході |

---

### `senders`

> Відправники Нової Пошти

| Поле                    | Тип           | Призначення                                                                                      |
| ----------------------- | ------------- | ------------------------------------------------------------------------------------------------ |
| `api_key`               | String        | API ключ з кабінету Нової Пошти (зберігається зашифровано)                                       |
| `full_name`             | String        | ПІБ відправника, підтягнуте з Нової Пошти                                                        |
| `phone`                 | String        | Номер телефону відправника, підтягнутий з Нової Пошти                                            |
| `np_counterparty_ref`   | String        | Ref контрагента в системі Нової Пошти                                                            |
| `np_contact_person_ref` | String        | Ref контактної особи в системі Нової Пошти                                                       |
| `addresses`             | Array<Object> | Кешований перелік адрес відправки, прикріплених до відправника (`np_address_ref`, `description`, `is_deactivated`) |
| `is_active`             | Boolean       | Ознака активного відправника (валідація: лише один `true` в колекції)                            |
| `is_deactivated`        | Boolean       | Soft-delete: замінює фізичне видалення відправника. UI-кнопка «Видалити» деактивує запис замість видалення з БД — старі замовлення (`orders.sender_id`) лишаються валідними. Деактивований відправник не може мати `is_active = true` |

**Структура елемента `addresses[]`:**

| Поле              | Тип     | Призначення                                                                          |
| ----------------- | ------- | ------------------------------------------------------------------------------------- |
| `np_address_ref`  | String  | Ref адреси в системі Нової Пошти                                                     |
| `description`     | String  | Опис адреси для відображення в селекті                                              |
| `city_ref`        | String  | Ref населеного пункту цієї адреси в системі Нової Пошти — потрібен як `CitySender` при створенні ЕН |
| `is_deactivated`  | Boolean | Soft-delete: приховує адресу з вибору при створенні замовлення, не видаляючи запис — старі замовлення (`orders.sender_address_ref`) лишаються валідними |

### `orders`

> Замовлення

| Поле                 | Тип                                  | Призначення                                                                     |
| -------------------- | ------------------------------------ | ------------------------------------------------------------------------------- |
| `order_type`         | ObjectId (ref → `order_types`)       | Тип замовлення: Кастомний / Сталий                                              |
| `shipment_type`      | ObjectId (ref → `shipment_types`)    | Тип відправки: Посилка / Документи                                              |
| `payment_type`       | ObjectId (ref → `payment_types`)     | Тип оплати                                                                      |
| `partial_amount`     | Number \| null                       | Сума післяплати. Заповнюється за умови типу оплати «часткова оплата»            |
| `total_amount`       | Number                               | Загальна вартість замовлення (розрахункове поле на основі `items`)              |
| `items`              | Array<Object>                        | Масив товарів у замовленні (embedded, див. структуру нижче)                     |
| `sender_id`          | ObjectId (ref → `senders`)           | Відправник, від імені якого створено замовлення                                 |
| `sender_address_ref` | String                               | Ref обраної адреси відправки Нової Пошти                                        |
| `recipient`          | Object                               | Дані отримувача (embedded, див. структуру нижче)                                |
| `delivery_type`      | ObjectId (ref → `delivery_types`)    | Спосіб доставки: Відділення / Адреса / Поштомат                                 |
| `delivery_details`   | Object                               | Деталі адреси доставки (embedded, див. структуру нижче)                         |
| `np_waybill_number`  | String                               | Номер накладної (ЕН), отриманий від Нової Пошти                                 |
| `np_waybill_ref`     | String                               | Внутрішній ref ЕН у системі Нової Пошти (для редагування/видалення)             |
| `shipment_status`    | ObjectId (ref → `shipment_statuses`) | Поточний статус відправлення, синхронізується автоматично через API Нової Пошти |

**Структура `items[]` (embedded):**

| Поле                 | Тип                                 | Призначення                                                                        |
| -------------------- | ----------------------------------- | ---------------------------------------------------------------------------------- |
| `product_id`         | ObjectId (ref → `products`) \| null | Товар з каталогу. `null` для кастомної наклейки                                    |
| `product_type`       | ObjectId (ref → `product_types`)    | Тип товару в межах позиції замовлення (Наклейка / Брелок / Кастомна наклейка)      |
| `name_snapshot`      | String                              | Назва товару на момент замовлення (знімок значення, важливо для кастомних позицій) |
| `photo_url_snapshot` | String \| null                      | Знімок фото товару на момент замовлення                                            |
| `price`              | Number                              | Ціна одиниці товару (з бази або кастомна)                                          |
| `is_promo`           | Boolean                             | Ознака продажу за акційною ціною                                                   |
| `quantity`           | Number                              | Кількість                                                                          |
| `subtotal`           | Number                              | Розрахункова вартість позиції (price × quantity)                                   |

**Структура `recipient` (embedded):**

| Поле          | Тип            | Призначення                 |
| ------------- | -------------- | --------------------------- |
| `phone`       | String         | Номер телефону отримувача   |
| `last_name`   | String         | Прізвище                    |
| `first_name`  | String         | Ім'я                        |
| `middle_name` | String \| null | По батькові, не обов'язково |

**Структура `delivery_details` (embedded):**

| Поле            | Тип            | Призначення                                                        |
| --------------- | -------------- | ------------------------------------------------------------------ |
| `city_ref`      | String         | Ref населеного пункту з довідника Нової Пошти                      |
| `warehouse_ref` | String \| null | Ref відділення. Заповнюється за умови `delivery_type = Відділення` |
| `street_ref`    | String \| null | Ref вулиці. Заповнюється за умови `delivery_type = Адреса`         |
| `house`         | String \| null | Номер будинку. Заповнюється за умови `delivery_type = Адреса`      |
| `apartment`     | String \| null | Номер квартири, не обов'язково. За умови `delivery_type = Адреса`  |
| `postomat_ref`  | String \| null | Ref поштомату. Заповнюється за умови `delivery_type = Поштомат`    |

## 📚 Довідники (dictionary collections)

> Довідники винесені в окремі колекції для гнучкого редагування значень без зміни коду. Кожен документ довідника, окрім службових полів, містить мінімум `code` (унікальний технічний код) та `label` (відображувана назва).

### `order_types`

> Довідник типів замовлення

| Поле    | Тип    | Призначення                                 |
| ------- | ------ | ------------------------------------------- |
| `code`  | String | Технічний код (напр. `custom`, `recurring`) |
| `label` | String | Назва: Кастомний / Сталий                   |

### `shipment_types`

> Довідник типів відправки

| Поле         | Тип     | Призначення                                      |
| ------------ | ------- | ------------------------------------------------ |
| `code`       | String  | Технічний код (напр. `parcel`, `documents`)      |
| `label`      | String  | Назва: Посилка / Документи                       |
| `is_default` | Boolean | Позначення значення за замовчуванням (Документи) |

### `product_types`

> Довідник типів товару

| Поле        | Тип     | Призначення                                                                 |
| ----------- | ------- | --------------------------------------------------------------------------- |
| `code`      | String  | Технічний код (напр. `sticker`, `keychain`, `custom_sticker`)               |
| `label`     | String  | Назва: Наклейка / Брелок / Кастомна наклейка                                |
| `is_custom` | Boolean | Ознака кастомного типу (не має записів у `products`, ціна вводиться вручну) |

### `payment_types`

> Довідник типів оплати

| Поле    | Тип    | Призначення                                        |
| ------- | ------ | -------------------------------------------------- |
| `code`  | String | Технічний код (напр. `full`, `cod`, `partial`)     |
| `label` | String | Назва: повна оплата / післяплата / часткова оплата |

### `expense_types`

> Довідник типів витрат

| Поле            | Тип     | Призначення                                                                   |
| --------------- | ------- | ----------------------------------------------------------------------------- |
| `code`          | String  | Технічний код (напр. `raw_poster`, `keychain_blank`, `delivery`, `other`)     |
| `label`         | String  | Назва: Сировина плакат / Заготовки для брелків / Доставка / Інше              |
| `requires_name` | Boolean | Ознака, що при обранні типу потрібне поле «Назва витрати» (`true` для «Інше») |

### `delivery_types`

> Довідник способів доставки

| Поле    | Тип    | Призначення                                              |
| ------- | ------ | -------------------------------------------------------- |
| `code`  | String | Технічний код (напр. `warehouse`, `address`, `postomat`) |
| `label` | String | Назва: Відділення / Адреса / Поштомат                    |

### `shipment_statuses`

> Довідник статусів відправлення (локальне відображення статусів Нової Пошти для фільтрів UI)

| Поле               | Тип      | Призначення                                                                                                  |
| ------------------ | -------- | ------------------------------------------------------------------------------------------------------------- |
| `code`             | String   | Технічний код (напр. `delivered`, `shipped`, `refused`, `received`)                                            |
| `label`            | String   | Назва: Доставлено / Відправлено / Відмовлено / Отримано                                                       |
| `np_status_codes`  | String[] | Коди статусів Нової Пошти (`StatusCode` з `TrackingDocument.getStatusDocuments`), що мапляться на цей статус — багато-до-одного (напр. `7`/`8` обидва → `delivered`) |

## 🔗 Примітки щодо зв'язків та підходу

- **Embedding vs Referencing:** позиції замовлення (`items`), дані отримувача (`recipient`) та деталі адреси (`delivery_details`) зберігаються вкладено (embedded) в документі `orders`, оскільки це дані, що читаються завжди разом із замовленням і не використовуються самостійно поза його контекстом — типовий підхід для MongoDB.
- **Довідники** винесені в окремі колекції (а не embedded enum) для можливості адміністрування значень без деплою коду та для консистентних `ObjectId`-посилань з інших колекцій.
- **Знімки даних (`_snapshot` поля):** назва та фото товару зберігаються знімком у позиції замовлення, щоб зміна товару в каталозі (`products`) заднім числом не впливала на вже оформлені замовлення.
- **Дані Нової Пошти** (населені пункти, вулиці, відділення, поштомати) не кешуються локальними колекціями — підтягуються напряму з API Нової Пошти на льоту, в БД зберігаються лише обрані `ref`-значення в межах конкретного замовлення/відправника.
- **Видалення відправника/адреси — soft-delete.** Кнопка «Видалити» на сторінці Відправники (`VOM_SYSTEMS.md`) виставляє `is_deactivated = true` замість фізичного видалення документа/елемента масиву — це зберігає валідність `orders.sender_id` та `orders.sender_address_ref` в історичних замовленнях без потреби в restrict/snapshot логіці.
- Рекомендовані індекси: `orders.np_waybill_number` (унікальний), `orders.created_at`, `products.type`, `expenses.type`, `expenses.created_at` (додано для фільтрації за періодом на сторінці дашборду), `senders.is_active`, `senders.is_deactivated`.
