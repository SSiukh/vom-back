Group by feature, not by technical layer (no top-level `controllers/`,
`services/`, `dtos/` folders holding every feature's files together). Each
feature is a self-contained module with everything it needs next to it:

```
src/
├── users/
│   ├── dto/
│   ├── entities/
│   ├── users.controller.ts
│   ├── users.service.ts
│   ├── users.module.ts
│   └── users.service.spec.ts
├── orders/
│   └── ...
├── shared/          # cross-cutting: filters, interceptors, pipes, utils
├── core/            # one-time init: DB setup, logging config
├── app.module.ts
└── main.ts
```

This is what makes a feature easy to move or delete as a unit.

## Module rules

- One module per feature. Export only what other modules actually need to
  import — do not export everything by default.
- `SharedModule` holds cross-cutting concerns (filters, interceptors, pipes,
  generic utils). Mark something `@Global()` only if it is genuinely needed
  everywhere — most shared providers should be imported explicitly instead.
- `CoreModule` holds one-time app-wide initialization (database connection
  setup, logging config). It is imported only by `AppModule`, never by
  feature modules.
- If `AppModule`'s `imports` array is growing past a handful of entries with
  no grouping, that's the signal to introduce a `CoreModule`/`SharedModule`
  split rather than keep flattening everything into it.

## Controllers vs services

Controllers handle HTTP (routing, status codes, request/response shape).
Services hold business logic. If a controller method has branching logic,
loops, or talks to more than one service to make a decision, that logic
belongs in a service instead.

## DTOs vs entities — keep them separate files, always

They look similar on day one and diverge as the project grows. Never merge
them and never return an entity directly from a controller.

- **DTO** (`dto/`): shape of data over the wire, validated with
  `class-validator` decorators (and carrying `@ApiProperty()` Swagger
  descriptions per `.claude/instructions/code-standards.md`), used by
  controllers.
- **Entity** (`entities/`): in this project the database shape is fully
  generated by Prisma Client, not hand-authored — there is no ORM class to
  write. `entities/<name>.entity.ts` still exists per feature, but only as
  a thin re-export/alias of the generated type (e.g.
  `export type Order = Prisma.Order;`, or a class extending it if a feature
  needs to attach behavior). Its purpose is a stable, feature-local import
  path — it carries no decorators and no hand-written fields.
- Controller → returns a DTO (map the entity/Prisma type to it in the
  service, or with a mapper) → never the raw entity/Prisma type, even if
  the fields currently match.

## Gotchas / anti-patterns to flag

- Circular dependencies between feature modules — usually means shared
  logic should move to `shared/` or `core/`, or one feature is doing too
  much.
- Business logic sitting in a controller instead of its service.
- A feature module importing another feature's `entities/` directly instead
  of depending on that feature's exported service/interface.
- Manually instantiating a provider with `new` instead of injecting it
  through Nest's DI container.
- One `AppModule` accumulating 40+ imports flat, with no `CoreModule` /
  `SharedModule` grouping.

## Naming / test placement

- Unit tests: `*.spec.ts` next to the file it tests (e.g.
  `users.service.spec.ts` beside `users.service.ts`).
- E2E tests: top-level `test/` folder, `*.e2e-spec.ts` files.

## Adding a new feature — checklist

- [ ] Create `src/<feature>/` with its own `dto/`, `entities/`,
      `<feature>.module.ts`, `<feature>.controller.ts`, `<feature>.service.ts`
- [ ] Controller depends only on its own service (thin, no business logic)
- [ ] DTOs validated with `class-validator`; entities kept in a separate file
- [ ] Module exports only the providers other modules genuinely need
- [ ] New module registered in `AppModule` (or in `CoreModule`/`SharedModule`
      if it's cross-cutting, not a feature)
- [ ] No direct cross-feature import of another feature's `entities/`
